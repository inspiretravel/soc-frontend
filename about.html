About · How it works

Real attacks in. Decisions out.

iPattern Threat Detector is a live proof-of-concept: a system that watches real attacks hit a decoy machine in Australia, and has AI write up each day's activity as a prioritised, framework-mapped case — the first-pass triage a security analyst would otherwise do by hand.

Pipeline

01 · capture
Honeypot
A real, exposed machine that mimics common attack surfaces — remote login, file sharing, web traffic — on a single Australian server.
02 · ship
Ingest
Log shippers post events to a private Flask endpoint. Every event keeps its timestamp, source IP and country.
03 · map
ATT&CK
Detection rules map each event to a technique from the full Enterprise set, loaded live from MITRE's STIX data.
04 · triage
AI case
Grouped events go to the Claude API server-side; it returns what happened, why it matters, what to do next.
05 · publish
This site
A static front end shows finished cases read-only. It holds no key and never calls the model.

Why this exists

Built from real SOC triage pain — too many alerts, too little time, and too much repetitive reporting — plus a decade of experience turning high-volume operational queues into fast, defensible decisions.

The goal: prove the first pass of threat triage doesn't need a human to start it. AI can read the evidence, apply the right framework, and hand over a decision a person can act on in seconds.

Key features

  • Full ATT&CK Enterprise technique set, refreshed from MITRE's STIX feed
  • Detection rules with AI enrichment; every case sentence traceable to grouped raw events
  • Essential Eight, NIST CSF 2.0 and ISO 27001:2022 mapping from the same evidence
  • Case management with analyst notes (backend)
  • Server-side credential proxy — the public site holds no secrets
  • Read-only public API; all attacker-derived text rendered as escaped plain text

Honesty notes

  • The triage prose is AI-generated. It has not been reviewed by an analyst. Treat it as a demo of the workflow, not as verified intelligence.
  • There is one honeypot node, in Australia. Attacks are reported by origin country, never by street address; the destination marker is region-level and the node's city is not named.
  • Every page reads one read-only public feed (/api/public/attacks) so pages cannot disagree. If the feed is unreachable the site falls back to a built-in sample and says sample data in the header. The feed serves stored triage only — no request to this site can trigger a model call.
  • Every technique ID links to attack.mitre.org so you can check the mapping yourself.
