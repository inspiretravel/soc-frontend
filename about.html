About · How it works

Real attacks in. Decisions out.

CyberTriageAI is a portfolio project built for a SOC L1 / Security Analyst job search in Australia. It runs one honeypot node in Melbourne, keeps every attempt made against it, and has an AI write each day's activity up as a prioritised, MITRE ATT&CK-mapped case — the first-pass triage a junior analyst would otherwise do by hand.

Pipeline

01 · capture
Honeypot
Cowrie (SSH / Telnet) and Dionaea (SMB, HTTP, FTP and more) on a single Melbourne node.
02 · ship
Ingest
Log shippers post events to a private Flask endpoint. Every event keeps its timestamp, source IP and country.
03 · map
ATT&CK
Detection rules map each event to a technique from the full Enterprise set, loaded live from MITRE's STIX data.
04 · triage
AI case
Grouped events go to the Claude API server-side; it returns what happened, why it matters, what to do next.
05 · publish
This site
A static front end shows finished cases read-only. It holds no key and never calls the model.

About the builder

10 years of enterprise SAP ERP incident ticketing — priority triage, SLA management, and escalation under pressure. Those workflows map directly to SOC work: same volume problem, same need to turn a queue into decisions.

I built this to demonstrate MITRE ATT&CK knowledge applied to real defensive telemetry — not just reading logs, but producing an actionable, framework-mapped write-up an organisation could act on.

SOC L1 / Security Analyst (AU)

Key features

  • Full ATT&CK Enterprise technique set, refreshed from MITRE's STIX feed
  • Detection rules with AI enrichment; every case sentence traceable to grouped raw events
  • Essential Eight, NIST CSF 2.0 and ISO 27001:2022 mapping from the same evidence
  • Case management with analyst notes (backend)
  • Server-side credential proxy — the public site holds no secrets
  • Read-only public API; all attacker-derived text rendered as escaped plain text

Honesty notes

  • The triage prose is AI-generated. It has not been reviewed by an analyst. Treat it as a demo of the workflow, not as verified intelligence.
  • There is one honeypot node, in Melbourne. Attacks are reported by origin country, never by street address; the destination marker is region-level.
  • Numbers on this site come from one shared data file so pages cannot disagree; the "live" motion on the map and dashboard is illustrative until the public API is wired.
  • Every technique ID links to attack.mitre.org so you can check the mapping yourself.
